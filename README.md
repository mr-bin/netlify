# Сайт Екатерины Заикиной — где что искать

Статический сайт (Jinja2-шаблоны + `script.py`), деплой на Netlify. Почти всё
содержимое сайта редактируется без изменения кода — прямо в файлах из
`data/` и `settings.yaml`, через браузер на GitHub.

## Инструкции по разделам

- **Видео** (список видео на главной странице) — данные в `data/videos.json`,
  инструкция для редактирования без терминов — [`VIDEOS_README.txt`](VIDEOS_README.txt).
- **Образование** (таймлайн обучения, членства/аккредитации, галерея
  дипломов) — данные в `data/education.yaml`, фото дипломов в
  `assets/documents/`, инструкция — [`education_readme.md`](education_readme.md).
- **Материалы** (PDF-листы для скачивания) — данные в `data/materials.yaml`,
  сами PDF в `assets/materials/`, инструкция — [`materials_readme.md`](materials_readme.md).
- **Тематические страницы** (отдельные страницы по темам, например
  «Поддержка после потери беременности» на `/poterya-beremennosti/`) —
  данные в `data/topics/` (один файл на страницу), инструкция —
  [`topics_readme.md`](topics_readme.md). Необязательные строки-ссылки на
  другое видео (пустая ссылка — строки нет, обе открываются в новой вкладке):
  `video.more_url`/`more_title`/`more_lead` — под блоком «Видео» (без
  `more_lead` пишется «Продолжение серии — в видео»; без `video.url` строки
  нет); `faq.items[].more_video_url`/`more_video_title` — «Подробнее — в
  видео «…» →» в конце ответа.
  Страница-подборка «Когда тревожно в ожидании» (`/trevoga-v-ozhidanii/`) —
  тоже файл в `data/topics/`, но с `type: practices` и своим шаблоном
  `practices.html.template` (см. `topics_readme.md`).
- **Статьи к видео** (текстовая версия видео, адрес `/video/<имя>/`, например
  `/video/psihosomatika/`) — один файл на статью в `data/video/`, шаблон
  `article.html.template`. Как добавить новую: скопировать
  `data/video/psihosomatika.yaml`, переименовать (имя файла = адрес),
  заполнить, сохранить и проверить адрес в `sitemap.xml`. Подробная
  подсказка — в начале этого файла. Правила: в `related` ссылка на другое
  видео — только если оно звучит в самом видео; после публикации адрес не
  меняем. Страницы-списка `/video/` нет. На тематической странице строку
  «Прочитать текстом →» под видео включает `video.article` (адрес статьи),
  под следующим видео — `video.more_article`; в конце ответа FAQ строку
  «Подробнее — в статье «…» →» — `faq.items[].more_article_url`/
  `more_article_title` (см. `topics_readme.md`).
- **Статьи без видео** (адрес `/stati/<имя>/`) — один файл на статью в
  `data/stati/`, тот же шаблон `article.html.template` и те же поля, что у
  статей к видео, только без полей видео и с обязательной датой публикации
  `published: "ГГГГ-ММ-ДД"`. Без `video_url` на странице нет блока видео, а
  для поисковиков вместо VideoObject выводится Article (картинка для соцсетей —
  фото профиля). Если позже вписать `video_url`, статья станет статьёй с видео,
  адрес останется `/stati/<имя>/`.
- **Страница «Статьи»** (`/stati/`) — подборка всех статей из `data/video/` и
  `data/stati/`, шаблон `stati.html.template`. Вступление, приглашение и список
  групп — в `data/stati-hub.yaml` (подсказка — в начале файла). У каждой
  статьи обязательны `topic` (ключ группы) и `card_text` (строка карточки, до
  140 знаков), необязателен `card_title` (короткий заголовок карточки вместо
  `h1`). Карточки собираются сами, внутри группы — от новых к старым; пустые
  группы не выводятся. На `/stati/` ведут строка «Все статьи →» в блоке
  «Видео» на главной и строка «Другие статьи — на странице «Статьи» →» в
  концовке каждой статьи (она зашита в шаблон).
- **Постоянные константы сайта** (цена консультации, цифры в hero/FAQ —
  сессии, клиенты, год начала практики, часы образования/терапии/супервизий,
  заголовок страницы `<title>`, адрес сайта) — в [`settings.yaml`](settings.yaml).
  Поменять число или текст там же в браузере на GitHub, без шаблонов.

## Как опубликовать правку

Любое изменение в `data/videos.json`, `data/education.yaml`,
`data/materials.yaml`, `data/topics/`, `data/video/`, `data/stati/`,
`data/stati-hub.yaml`, `settings.yaml`, `assets/documents/` или
`assets/materials/` достаточно сохранить («Commit changes») на GitHub —
Netlify пересоберёт и обновит сайт сам, через 1–2 минуты. Отдельного шага
публикации не нужно.

## Локальная сборка (для разработки)

```
pip3 install --user -r requirements.txt
python3 script.py
cd public && python3 -m http.server 8765 --bind 127.0.0.1
```
затем открыть http://127.0.0.1:8765/
